## Goal

The orchestrator: retained audio → corrected, speaker-named transcript + rendered notes + enqueued handoff, end to end on the real sample; the pinned regression artifacts + automated checks; regeneration; crash-safety evidence.

## `ProcessingPipeline` (actor, single-flight FIFO chain)

**Captured-meeting variant (C11, body amendment):** `processCaptured(meetingID:)` — two retained tracks; ASR per track; mic track labeled `user`/named UserIdentity at creation; system track diarized+merged; cross-track echo suppression (raw-ASR level, before the mic merge); interleave by start with the pinned tie-break (start, mic-first, ord; ord re-sequenced; per-track invariants); correction onward unchanged. `regenerate()` dispatches by track inventory (`audio_mic.m4a` present → this variant). File-first `process()` unchanged.

**Cross-track echo dedup (v3.8; raw-ASR granularity, before the mic-track merge):** without headphones the system track's audio bleeds acoustically into the mic, so the mic track grows near-duplicate segments of OTHER speakers' words under the user's label. Suppression runs on each track's RAW ASR segments, before SpeakerMerger consolidates the mic track: consolidation grows user turns up to minutes, so a MIXED turn (genuine user speech with an embedded echo of the other speaker) can never cross a whole-segment similarity gate, while raw whisper segments (~2 s) discriminate cleanly; the merge then consolidates only the survivors. A raw MIC segment is dropped as echo iff (a) its span overlaps system segments within ±1.5 s (codec/transcription jitter), (b) it carries ≥ 5 normalized tokens (case/diacritic-folded, punctuation-stripped — short utterances like "sim"/"ok" are NEVER dropped), and (c) its token sequence matches the concatenation of the overlapping system segments' tokens (start order) at ≥ 0.85 similarity via order-respecting token edit distance with free leading/trailing system tokens — order sensitivity blocks bag-of-common-words false positives; the window concatenation catches bleed that whisper consolidated across system speaker turns; at 5 tokens the threshold demands an exact match. Only the mic copy is dropped: its `user` label is assigned by construction, the system copy's attribution is diarization-grounded. The symmetric direction (the user echoing into the SYSTEM track via a remote participant) is deliberately NOT suppressed — dropping a system segment risks deleting another participant's genuine words, remote echo requires the far end's echo cancellation to fail (rare), and its damage is a redundant duplicate under an S-label, not loss. Drops are counted in the run record (`echoDroppedSegments` — RAW mic ASR segments dropped, not merged turns); routine, no processingNote. The file-first path and the Tier-1/Tier-2 regression pins (single-track by construction) are untouched.

`process(meetingID:)` (sets `status = processing` at entry) and `regenerate(meetingID:)` (status untouched — C1 no-regress; `processingNote` cleared at entry per C6). One run in flight app-wide; cancellation kills the active stage's subprocess; temp artifacts (decoded WAV) deleted on every exit path.

**Stages:**
1. `ingest` (process() of an import only; **regenerate() NEVER runs ingest** — it starts at stage 2 from retained audio): copy source WAV into the meeting dir; encode retained `audio.m4a` (D7) **via temp + atomic rename, ONLY if absent** (C1 retention: audio is never overwritten); the import copy is deleted ONLY after the encoded m4a passes a verification decode (opens, duration within 0.5 s of the source — hard floor 2: never discard the lossless copy on an unverified encode). Re-runs: encode step reads the in-dir copy if present, else the original wavURL; after a mid-ingest crash with the copy gone and no verified m4a, process() fails with a named error (source required).
2. `transcode` — decode retained `audio.m4a` → temp 16 kHz mono Int16 WAV (AVAudioConverter; `close()` finalizes — probed). First run ≡ regeneration by construction (decision D14: always transcribe from retained audio; the measured AAC-32k cost is word-similarity 0.969 on the probe slice, filler-level differences only; runner-up — transcribe imports losslessly — rejected for path divergence; logged in an internal decision record).
3. `asr` — resolve (C2) → `prepare()` → `availability()` (unavailable → run fails with the named reason) → transcribe. `raw_asr.json` written; **ASRProvenance held IN MEMORY** — it persists to the meeting row only at stage 11 alongside the transcript it describes (C1: provenance is set when the transcript is (re)written; a failed regeneration must never re-label the old transcript).
4. `diarize` — C4 diarizer on the same temp WAV.
5. `merge` — C4 SpeakerMerger.
6. `correct` — C5 corrector (bundled fixtures — bundling is this chunk's AC; corrections logged).
7. `languageStats` — `DominantLanguage.classify(segments:)` (C6-pinned classifier; committed word sets; tie → "pt"); held in memory, persisted at stage 11.
8. `resolveSpeakers` — C4 resolve (hints: stored events + recordingStart; file-first usually none) → `apply()` mechanical pass (in-memory).
9. `notes` — resolve → prepare → `generateNotes` directly: **NO availability gate at this stage** — C6's design routes ceiling/budget/config conditions through THROWN triggers (`inputTooLong`/`outOfMemory`/`monthlyCeiling`/`insufficientMemory` constants + `.configurationMissing`) so the one-hop fallback can fire; a pre-gate would kill the run the fallback exists to save. (The asr-stage gate stays: ASR has no fallback contract.) The C2 availability contract is AMENDED for the summarization slot (recorded in C2's changelog): C7 skips the pre-gate there by design. **D17 weight-class bound: the hop only AUTO-fires when the fallback engine declares `loadProfile == .lightweight`; a heavyweight-only fallback resolves the stage to the NOTES-PENDING outcome instead** — the run continues (stage 10 is skipped: no proposals exist; stage 11 persists the transcript as always) and ends pending: reserved `lastProcessingError = "notes-pending: <reason>"` (`NotesPendingClass` constant; UI and dispatch key on the prefix, never on free text), process()-class runs land `failed` (NOT ready — ready ⇒ queued holds; NO handoff is enqueued), regeneration-class runs keep their status with the previous notes intact (the marker surfaces the mixed generation). A heavyweight engine still runs as the user's deliberate PRIMARY selection (its own memory gate applies — C6). **The lightweight fallback hop runs `prepare()` on the fallback engine first** (engines' prepare is idempotent and cheap-when-satisfied by contract). Both-fail → stage failure, both reasons recorded.
10. `applyLLMNames` — drop `low`-confidence proposals → `apply()` (validated; mechanical names win by no-overwrite). All naming is now final, in memory.
11. `persistTranscript` — **the single transcript persistence point, AFTER all naming**: replace-all segments (FTS synced) + write `Meeting.asrProvenance` + `Meeting.dominantLanguage` updates in the same write + export `transcript.json`. Nothing downstream mutates segments.
12. `persistNotes` — render (language = `Meeting.dominantLanguage`) → persist markdown + structured + provenance (incl. promptVersion; `pipelineVersion` = the C7-owned constant `PipelineVersion.current`, format "<major>.<minor>" starting "1.0", bumped on ANY change that alters pipeline output — the Tier-1 byte-pin enforces honesty: an unbumped output-changing edit fails the pin); `MeetingNotes.language` = the same value; export `notes.md`.
13. `finalize` — C8 builder (reads the now-final DB state) → immutable payload write → `finalizeMeetingProcessing` (status=ready + enqueue, one transaction) → `HandoffWorker.kick()`.

**Notes-only resume (D17 self-heal):** `processNotesOnly(meetingID:)` resumes a notes-pending meeting WITHOUT re-running ASR (a full reprocess costs 2–3 min and 3–5 GB per retry): it first absorbs any `meet_roster_pending` rows queued while the meeting sat pending into `meeting.attendees` (the C10 absorption point is the full run's entry, which the resume bypasses; the resume is a sanctioned content write followed by a fresh mint — `updatedAt` bumps only when an attendee was actually added; late speaker EVENTS need no equivalent: the resume reads `meeting_speaker_event` fresh), then rebuilds the `NotesRequest` from the persisted DB transcript + meeting row (segments, `dominantLanguage`, attendees and the bundled vocabulary are all durable; absent late roster, the rebuilt request assembles byte-identical prompts to the pending run's stage 9 — the persisted segments ARE that run's stage-9 transcript, since a pending run applies no LLM names; pinned by a request-equality unit test), then runs notes → LLM-name application (re-persisting the transcript only when a proposal actually named someone) → persistNotes → finalize (notes upsert + status=ready + handoff enqueue in `finalizeMeetingProcessing`'s one transaction) → handoff kick. Runs on the single-flight chain like every entry point; returns nil (no-op) when the meeting is no longer pending — race-safe against a concurrent full reprocess by serialization + that guard. The converse direction holds too: the status-dependent dispatch (`dispatchProcessing`) takes its process-vs-regenerate decision INSIDE its chained body, so a kick racing a resume sees the resume's terminal state and a healed (now-`ready`) meeting dispatches as a regeneration — C1 no-regress holds even though the healer flips failed → ready as a background event. Resume failure KEEPS the meeting pending (marker refreshed with the new reason; marker writes never bump `updatedAt` — bookkeeping, not content, per C1's content-only rule). Known window while a regeneration-class pending state persists (`ready` + marker — potentially days under D17, vs seconds pre-D17): the queued OLD payload is not re-materializable from durable state (stage 11 already re-persisted a newer transcript), so a lost/corrupt payload file in that window quarantines visibly as `damaged:` and is superseded by the healed delivery — no silent loss. `resumePendingNotes()` is the trigger entry — app launch, any saved config field of a registered summarization engine in Settings (the Anthropic API key lands here; a venv/HF-home path fix can equally unblock an MLX-primary pending), and network-path RESTORATION (NWPathMonitor, the C8 pattern; the initial current-path delivery and interface flips while satisfied do not re-fire — the launch kick covers launch) each call it; month rollover needs no trigger of its own (the ceiling is re-evaluated on the next attempt; launch/network cover it).

**Progress:** `AsyncStream<PipelineEvent>`. **Failure semantics:** process() failure → `failed` + stage-tagged `lastProcessingError`; regenerate() failure → status stays `ready`, error recorded. **`processingNote` contract (single writer per run): cleared at EVERY run entry (process and regenerate); set at most once by the terminal event — a successful run with a fallback sets the fallback note; a partial regeneration failure sets a stage-accurate note ("partial regeneration: transcript updated; <failed stage> failed") — this second writer class is a recorded C1/C6 amendment (their changelogs note it); a regeneration failing BEFORE stage 11 sets no note (nothing durable changed; lastProcessingError carries the failure); both writer classes never combine (the failure note wins).** Mixed-generation local artifacts (new transcript, older notes) are exactly what that note surfaces; the delivered payload is only replaced by a successful finalize, so the Evidence Store never sees a mixed state.

## Regression pin (the ICSI fixture — Tier-1 byte-pin and Tier-2 audio smoke)

The regression fixture is a real, openly licensed meeting clip: a ~5-minute excerpt of the ICSI Meeting Corpus (meeting `Bmr001`), CC BY 4.0, committed under `fixtures/icsi_sample/` (the `Bmr001_excerpt_5min.wav` clip plus `ATTRIBUTION.md` and `LICENSE-CC-BY-4.0.txt`). Real consented academic multi-speaker English meeting speech, redistributable with attribution; the directory is NOT under the project's MIT license and the CC-BY attribution must be preserved on redistribution. Speech recognition and diarization are NOT bit-reproducible (Metal/MLX), so their outputs over this clip are frozen ONCE — committed as fixed inputs, never re-run in CI; the deterministic post-ASR transform over those frozen bytes is what the byte-pin enforces.

- **Committed pins (frozen inputs + deterministic outputs):** `raw_asr.json` (the frozen ASR over the clip), `diarization.json` (the frozen diarization), `transcript_intermediate_pinned.json` (post-correct, pre-naming — deterministic by construction over the frozen inputs), `transcript_pinned.json` (final, speaker-named), and `pin_manifest.json` (engine identities and versions, audio + frozen-input/output hashes, source excerpt range, and the license/attribution fields). All under `fixtures/icsi_sample/`. These are re-derived by a one-time LOCAL mint (run ASR + diarization once on the clip, then the transform; no cloud key needed) — see the project plan and an internal note.
- **Tier 1 (always-on, no models, CI-safe):** committed inputs (`raw_asr.json`, `diarization.json`) → normalizer → merge → correct → languageStats → name resolution → transcript assembly in-process → BYTE-compare vs the committed pins (`transcript_intermediate_pinned.json`, `transcript_pinned.json`). Runs with no model load and no key, so it is the public CI's deterministic regression guard. The byte-compare is over canonical sorted-keys JSON; the pins are re-minted only on an intentional output-changing edit (the `pipelineVersion` bump rule above keeps that honest).
- **Tier 2 (audio smoke, gated `BLAISE_TEST_FULL_SAMPLE=1`):** runs ASR live on the clip and asserts STRUCTURAL sanity only — `detectedLanguage == "en"`; no NaN/negative segment times; `endSeconds ≤ audioDuration` (300.0 s); a sane segment count and ≥ 2 diarized speakers; a few stable English function words present. This proves the system actually hears audio end to end; it does NOT byte-compare (live ASR is non-deterministic). It uses a TEST-scoped handoff remoteRoot (C8's `_test/<run-ULID>` convention) and tolerates the remote host offline.
- **Notes arm (cloud-key-gated):** the notes-synthesis step needs a capable cloud model, so it stays key-gated and SKIPS cleanly when no key is present (recording the reason), exactly as the rest of the suite. On a keyless machine the cloud primary trips `.configurationMissing` and, the only fallback being heavyweight, the run resolves to the D17 notes-pending outcome (reserved marker set, transcript persisted, notes absent, NO handoff row).
- Evidence of the in-chunk run → an internal audit record.

## Crash safety (engine realism stated)

- **Real-engine timing kill (one):** kill -9 mid-ASR on the ICSI-clip meeting → audio.m4a byte-identical, orphan driver reaped at relaunch, status swept `failed`, re-run succeeds.
- **Deterministic kill points (MOCK engines — the only honest way to assert byte-level no-ops):** `BLAISE_CRASH_AT` hooks: mid-ingest-encode (temp file present, `audio.m4a` ABSENT or complete — never truncated), mid-persistTranscript **inside the transaction via C1's existing `midTransactionHook` seam** (WAL atomicity: consistent DB, FTS integrity), between payload-write and finalize (mock determinism → reprocess: immutable writer no-ops, finalize completes, exactly one queue row). With real engines the same point produces a new hash + orphaned old payload — stated, not asserted away.
- Evidence → an internal audit record.

## Code-switching coverage (opportunistic-local + a synthetic bilingual guard)

The ICSI clip is English-only, so Portuguese/English code-switching is covered two ways. **Opportunistically against a local meeting corpus, when present:** an opt-in, read-only test (gated `BLAISE_TEST_LOCAL_CORPUS=1`) snapshots the local Blaise data root via the SQLite backup API to a temp file (never opening or mutating prod, which may be recording), selects the newest `ready` meeting, and asserts structural sanity over its persisted transcript (counts only — transcript text is never echoed to logs or assertions); when no local corpus is present it skips cleanly and records the reason to `.test-skips/`. This is never committed. **And a synthetic bilingual transform-boundary guard:** a hand-authored, audio-free `raw_asr.json` + `diarization.json` carrying Vexatron-universe PT/EN code-switching, byte-pinned through the deterministic transform exactly like the ICSI Tier-1 pin. It gives CI a deterministic bilingual regression guard without any audio or model — it fills the code-switching gap the English-only clip leaves and runs everywhere.

Unit: stage sequencing/failure-tagging with mock engines (every stage failure → correct status/error/processingNote per rules; regenerate skips ingest; process sets processing); DominantLanguage classifier; ingest encode (if-absent guard: second run no-ops; atomic: injected mid-encode failure leaves no audio.m4a) + transcode round-trip; Tier-1 harness mechanics (byte-stable, run twice).
2. Pins minted + committed (frozen `raw_asr.json` + `diarization.json` inputs, the intermediate + final transcript pins, and a decode-safe `pin_manifest.json` with engine versions, audio + frozen-input/output hashes, and license/attribution fields); Tier-1 byte-pin always-on; Tier-2 audio smoke implemented, gated `BLAISE_TEST_FULL_SAMPLE`, **executed in-chunk** with evidence.
3. Crash evidence per above.
4. Regeneration: delete transcript → `regenerate()` → valid transcript artifacts from retained audio (the keyless light run asserts the notes-pending outcome alongside); engine-switch regeneration for BOTH slots — the ASR switch under the light gate, the summarization switch (heavyweight load) under the NOTES gate — provenance reflects each; unavailable second summarization engine → recorded skip.
5. `importMeeting(sourceURL:title:startedAt:attendees:meetingCode:)` seam (WAV or M4A; M4A = verified copy, no re-encode); C5 fixture bundling into the app resources.
