## Goal

A passive MV3 extension that, while the user attends a Meet call in their own browser, captures the participant roster and active-speaker events and delivers both to the Blaise app on localhost — buffering when the app is down. No bot, no automation, passive DOM observation only. Loadable unpacked.

**Consumer honesty:** until the app-side listener lands (C10/C11 integration), delivered events have no consumer and buffered events eventually ring-drop. That is a sequencing fact of the file-first plan, stated here and in the project plan.

## Capture design

- **`selectors.js` — single rotation point**, structural/data-attribute strategies (`data-participant-id`, `data-requested-participant-id`, legacy `data-self-name` divs, People-panel semantics), each annotated with source + last-verified date. Localized text banned except the three bounded carve-outs (self-tile labels, leave-button labels, pin-label name templates), all replaced by structural markers discovered from the real snapshot at the Human Touchpoint.
- **Current-Meet name extraction (field-verified 2026-06-11):** live tiles carry BOTH `data-participant-id` and `data-requested-participant-id` (values `spaces/<space>/devices/<n>`); `[data-self-name]` is gone. Name reads therefore (a) exclude icon-font elements (`google-symbols` etc. — ligature text like `keep_outline` otherwise glues onto labels) and button/menu/tooltip subtrees; (b) mine the tile pin-control label for the embedded full display name (carve-out #3: pt-BR template "Fixar \<name\> na tela principal" field-verified; en counterpart unverified) when no plain name position exists; (c) reject any candidate still containing an underscore (icon-ligature signature) — nil name beats wrong name. Speaking attribution classifies panel rows by `role="listitem"`, never by attribute presence (tiles carry the panel attribute too). The legacy `data-self-name` path is retained for older DOM shapes. Fixture `meet_in_call_2026.html` is a labeled reconstruction from the field wire batches, not a full live-DOM dump.
- **Self model (participantID-anchored, honest about misses):** the self TILE shows a localized label ("You"/"Você" — meaningless as a name); the People-panel self row shows the real account display name. Rules: (1) a tile whose name position exactly matches the CLOSED set {"You", "Você"} (bounded interim carve-out; replaced by the snapshot-derived structural marker at the Touchpoint) is self → emitted with `isSelf: true`, **`displayName: null`** (no meaningless label ever travels; the consumer MUST substitute `UserIdentity.name` — there is no name to fall back on), and its `participantID` when present; (2) once a self participantID is known, ANY entry (tile or panel) with that participantID is self (same null-name treatment); (3) a panel self row NOT linked by participantID flows as an ordinary named participant — this is a stated, harmless miss: it carries the real account name, which C4's voting + the user's aliases resolve correctly; the contract doc instructs the listener to merge identities sharing a participantID, preferring the named form for display and the isSelf flag for substitution. A total detection miss degrades to correct-but-unflagged attribution for PANEL-sourced names. Residual risks stated honestly: (a) a ROTATED self-tile label outside the closed set would travel as a junk displayName — the LISTENER therefore normalizes: any displayName in the localized-self denylist {You, Você, you, você} is treated as isSelf (contract-doc rule; belt to the wire-level braces); (b) a partial miss (unlinked self tile + named panel row) splits the self vote across two identity keys and may leave the self cluster unresolved under strict dominance — graceful degradation (nil name, never wrong name), recorded.
- **In-call lifecycle:** capture armed only in joined state. Interim detector: in-call control bar presence by structural position (bounded carve-out #2 if a localized aria-label is unavoidable — same Touchpoint-replacement treatment as self-tile; stated honestly rather than claimed structural). Pre-join preview produces nothing. Leave detection or `pagehide` → final flush.
- **Roster:** rendered tiles continuously + People panel WHEN OPEN (never opened by the extension; tiles under-count without it — documented; README suggests the one-click habit; D13).
- **Active speaker:** MutationObserver (`attributeFilter:["class"]`, subtree) → visibility-checked ticks → per-participant coalescing (merge gaps ≤ 3000 ms, drop < 500 ms) → events with `Date.now()` epochs. Panel-row speaking indicators also observed when the panel is open. Off-tile participants in large layouts produce no events (documented limitation).
- **Meeting identity:** `meetingCode` from the URL path, in every batch.
- Observer resilience: body-level sentinel re-attaches on container replacement; ≤ 10 Hz processing.

## Delivery (encrypted — D13 as amended)

- **Shared secret:** generated by the app (32 random bytes, hex), shown in Settings with a REVEAL + REGENERATE control (not shown-once; rotation = paste the new value into the options page; a stale secret surfaces as the persistent badge below). The user pastes it into the extension options page once (Human Touchpoint, ~30 s).
- **Transport security (one mechanism, no handshake protocol):** every batch is encrypted **AES-256-GCM** via WebCrypto: key = SHA-256(secret) imported as AES key; fresh random 12-byte IV per message; AAD = `"blaise-meet-events-v1"`. `POST /v1/meet-events` body = `{iv, ciphertext}` (base64). Properties: a port-squatter receives ciphertext only (zero exfiltration even mid-meeting if the app dies and a squatter binds the port); forgery is impossible without the secret (AEAD authentication); there is no plaintext-HMAC oracle because there is no challenge endpoint and no HMAC bearer. Decryption failure at the app → 401; the extension surfaces a persistent "check secret" badge after 3 consecutive 401s and keeps buffering (bounded by the ring).
- **Signed acknowledgments (delivery decisions never trust bare status codes):** every app response carries `X-Blaise-Ack: HMAC-SHA256(ackKey, "ack-v1:" + base64(IV) + ":" + <status>)` with `ackKey = SHA-256(secret || "ack")` (domain-separated from the AES key; base64 IV cannot contain the `:` delimiter; pinned in the contract doc). The extension marks a batch delivered ONLY on a VALID signed 200; a signed 400 → drop + `poisonedCount`; a signed 401 → badge path; ANY unsigned response (whatever the status — a port-squatter can fabricate codes but not signatures) → network-class failure → ring retry. A squatter can therefore neither receive plaintext, nor forge events, nor cause silent loss by fake-acking. Badge "connected" = age of last valid ack (no separate ping endpoint — one less surface).
- **Batch plaintext schema (inside the encryption):** `{meetingCode, capturedAtMs, droppedCount, poisonedCount, roster: [{displayName|null, participantID?, isSelf}], events: [{displayName|null, participantID?, isSelf, startEpochMillis, endEpochMillis}], schemaVersion: 1}`. Closed utterances only; dedupe id = `meetingCode:participantID-or-displayName-or-self:startMs:endMs`.
- **Buffering:** failed POSTs → `chrome.storage.local` FIFO ring (10k events; ring losses ride `droppedCount`); `chrome.alarms` retry (minimum interval verified at implementation; the worker re-creates a missing alarm at every start). Status contract: 400 → drop batch + `poisonedCount`; 401 → badge path above; 5xx/network → ring retry. Every delivery fetch carries a 15 s abort timeout: a port holder that accepts the connection and never answers classifies as a network failure instead of wedging the manager for the worker's lifetime.
- **Contract doc (`docs/meet_events_contract.md`):** schema, crypto parameters, ack protocol, substitution rule, **correlation rule: a batch matches the meeting with the same `meetingCode` whose [startedAt − 10 min, endedAt-or-now + 10 min] window overlaps the events; ambiguity resolves to greatest event-overlap duration; a meeting WITH AN ACTIVE RECORDING SESSION correlates live (C11's case); otherwise at meeting close; unmatched events retained 7 days then discarded** — plus port-collision behavior, roster under-count note, and the residual-risk statement (ciphertext-only exposure to squatters; a process reading the browser profile owns the browser — out of threat model).
- **Listener obligations (contract doc, binding on C10/C11):** decrypt + signed-ack protocol; isSelf substitution + participantID identity-merge; **display-name sanitization mirroring the extension** (pin-label name extraction + icon-ligature junk rejection, applied at normalize time; RAW wire fields stay untouched so dedupe ids are byte-stable) — pre-0.2.0 extensions buffered dirty names and replay them after update; **bind policy: an app instance running with a `BLAISE_DATA_ROOT` override never binds 18429** (opt-in `BLAISE_MEET_LISTENER=1` for deliberate integration tests) — dev/demo instances share the Keychain secret and would otherwise swallow live batches into throwaway databases with valid signed 200s; **replay/dedupe: a per-meeting seen-id set (retained with the meeting) and a ±48 h freshness window on `capturedAtMs`** — AEAD does not prevent replaying a captured legitimate ciphertext; dedupe does. **Cross-chunk contract test obligation:** this chunk commits `test/fixtures/wire_batch_golden.json` (encrypted batch + test secret) and `expected_ingestion.json` (post-substitution ActiveSpeakerEvents incl. an isSelf case and a replayed duplicate that must ingest once); the C10/C11 listener's acceptance MUST consume both.

## Tests (no Chrome needed for the suite)

Fixture-hygiene test asserts: no `@`, no `http(s)://`, no surviving non-allowlisted attributes, and (locally) no value whose digest appears in the sidecar.

## Acceptance criteria

1. `cd extension && npm test` green; wired into scripts/test.sh (node present — verify).
2. **Unpacked-load smoke via Chrome for Testing** (branded Chrome blocked `--load-extension` in 137 — source URLs recorded in internal research notes): dev-time script downloads the CfT binary (`npx @puppeteer/browsers install chrome@stable`, not committed), launches `--headless=new --load-extension=<path> --remote-debugging-port`, and asserts THE OBSERVABLE: the extension's service worker appears in the DevTools target list (vacuous-pass impossible). CfT unavailable offline → manifest schema validation + recorded DoD split.
3. `docs/meet_events_contract.md` written (all items above) + the wire/ingestion golden fixtures committed.
4. README privacy note (names + speaking times + meeting code only; encrypted to localhost only).
5. No regression in the Swift suite. D13 amended in an internal decision record (AEAD design, signed-ack protocol, secret lifecycle [app side: Keychain via C2 SecretStore], CfT smoke).
