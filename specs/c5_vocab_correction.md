## Goal

Deterministic post-ASR correction of the user's curated vocabulary: restore canonical spelling (case, diacritics) of known terms and apply curated, evidence-driven mishearing aliases — and TOUCH NOTHING ELSE (hard floor 1). No fuzzy matching (D9 as amended). Pure BlaiseCore + tests; pipeline wiring is C7.

## Scope (honest, post-D9-as-amended)

| Failure mode | Handled by |
|---|---|
| `nara`→`Nará`, `kovo`→`Kovo` (case/diacritic restoration of distinctive terms) | C5 exact stage |
| `Vexo`→`Vexa` (sample-observed mishearing whose surface form is NOT a real word/name — see alias admission rule), `OKR X`→`OKRX`, `NVR 2`→`NVR2` | C5 alias stage (curated) |
| `Fábio`, `Kiko`, `nimbus`, `nebula`, `aurora`, ordinary speech & other people | Never touched — no fuzzy; exact-stage FP surface scanned at derivation (below) |
| `sink`→`sync` (real-word mishearing), `Creat of Trust` (non-glossary term), contextual named-entity-vs-ordinary-word casing (the company name vs the ordinary word; a product name vs the ordinary word it shadows) | C6 LLM vocabulary instruction (sees full canonical list) |
| Accent-ADDED mishearings (e.g. ASR writes `Tomás` for spoken Tomas) | **Accepted false negative** — diacritic-exact alias semantics protect real people named Tomás at the cost of missing this direction; documented, judged in C7 sample runs |

**DoD dependency, stated:** the Appendix-A vocabulary item is delivered by C5 (this engine) + the **C7 calibration loop**: run pipeline on the sample → inspect vocab survival → admit new aliases under the admission rule → re-run. Mishearings whose surface form fails the admission rule (real words like "sink") are constitutionally out of C5's reach and are delegated to C6's instruction; if any such case occurs for a vocab term IN THE SAMPLE, C7 must record it in the internal open-questions log and the DoD item is judged with that documented division (transcript-level fix impossible without unsafe substitution — honesty over completion).

## Decision amendment (recorded here, applied to an internal decision record)

D9's rationale listed "Vexo" alongside "sink" as unsafe for blind substitution; that grouping conflates two classes. Amended principle: **blind substitution is unsafe when the misheard SURFACE FORM is itself a real word or plausible name; it is safe when the surface form is lexical garbage that can only be the mishearing.** "Vexo" (not a PT/EN word, not a name in br_common_names, evidenced in the DEFAULT engine's sample-transcript oracle) is admissible; "sink" is not. The admission rule below operationalizes this.

## Inputs

1. **`fixtures/synthetic_vocab.txt`** — regenerated by the derivation pass. Grammar (normative): `# comment`/blank ignored; `canonical` or `canonical|alias1|alias2|…`; `,` has no syntactic meaning; fields whitespace-trimmed including `\r` (CRLF-safe, G1 §2); an empty canonical = malformed (skip + surfaced warning); an empty alias field is dropped field-wise — the entry survives on its remaining fields, also surfaced (G1 §2 amendment, shared with the user-glossary wrapper). Derivation asserts no glossary term contains `|`; aliases contain no punctuation other than apostrophes.
2. **`fixtures/stoplist_pt.txt` / `stoplist_en.txt`** — vendored frequency lists. TWO cut levels used: **top-3000** (the collision-policy suppression set) and the **full vendored list (~50k)** (the lexicon for the collision scan and alias admission). Source hermitdave/FrequencyWords (license verified + recorded in header; fallback: wordfreq data, recorded).

4. **`fixtures/stoplist_exclusions.txt`** — words that must NOT act as suppression stop-words regardless of vendored-list membership (defensive override; behaviorally asserted in ACs, e.g. "quest" must be non-stop for the mixed-window AC whatever its rank).

## Dictionary derivation pass (committed script, rerunnable, emits `synthetic_vocab.manifest.json`)

- Order: author br_common_names FIRST; then keep current entries; ADD standalone distinctive first names of glossary people iff not in br_common_names — the lexicon check uses disposition rule (ii): a lexicon hit that is name-shaped does not block admission (e.g. "renato" ranks high in subtitle lists *as a name*; case-restoring it is correct), a common-WORD hit does. ADD spaced-compound aliases by inspection, each justified in the script and passing the **alias-core scan**: a multi-token alias is REJECTED iff ALL of its folded cores are lexicon-common (member of either full ~50k list at rank ≤ 40000) — such a token sequence occurs in ordinary speech, and alias windows have no runtime suppression branch, so it would rewrite ordinary speech; one distinctive core admits. Shipped: OKRX|OKR X, NVR2|NVR 2 ("okr"/"nvr" are not lexicon words). Rejected, recorded in the manifest: Silver Fox|silver fox, Open Door|open door (silver+fox, open+door all common EN words). The scan also runs as a derivation-failing assertion over EVERY shipped multi-token alias, whatever its source.
- ADD observed-mishearing aliases passing the **alias admission rule**: alias (folded) must be (a) absent from the full ~50k lexicons as a common word (name-shaped hits judged per disposition rules), (b) absent from br_common_names, (c) non-colliding (below), (d) judged against the accent-drop direction: could the alias be the accent-stripped form of a plausible real name (the failure shape that killed `Patrisia|Patricia`, where the alias is the accent-stripped form of the real name `Patrícia`)? Shipped: `Vexa|Vexo` — admission record: not a PT/EN word; not in br_common_names; **residual risk accepted and documented: "Vexo" is also accent-dropped "Vexá" (a plausible BR surname) — judged acceptably improbable in the user's meetings, evidenced as a mishearing of Vexa in the synthetic transcript fixtures, and overridable by C6 context**. NOT shipped: `Patrisia|Patricia` (collides with the real BR given name Patrícia in exactly the accent-drop direction AND unnecessary — the name is already spelled correctly by the ASR engine), `sync|sink` (real word).
- **Collision assertions:** across ALL entries, no folded surface form (canonical or alias) may map to two different canonicals; duplicates mapping to the same canonical are merged. Violations fail derivation.
- **Exact-stage FP collision scan (two levels):**
  - *Level A (single-token):* every folded single-token surface form (canonical or alias) is checked against the FULL ~50k lexicons.
  - *Level B (multi-token):* for every multi-token entry, each token CORE's membership in the effective suppression set is computed and the entry is classified: fully-suppressible (all cores stop-listed → its case-only corrections will be suppressed; delegated to C6) or mixed (will fire). The classification is REPORTED in the manifest, and **Level-B review carries DISPOSITION AUTHORITY: where a mixed entry's firing would corrupt ordinary speech (its non-stop cores are real PT/EN words by lexicon-50k or reviewer judgment — e.g. "aurora", "drift"), the reviewer adds those cores to stoplist_project with a recorded justification, flipping the entry to fully-suppressible.** Re-derivation flags reclassifications.
  - *Disposition rules (each Level-A hit gets exactly one, recorded in the manifest):* (i) the hit is a common WORD whose rewrite would corrupt ordinary speech (nimbus, aurora, drift, orbit, nova class) → add to stoplist_project (suppression); (ii) the hit is name-shaped — it appears in lexicons as a proper name, not a common word (vexa, marsh, driftwood, renato class; subtitle frequency lists are full of names) → ACCEPT with justification: case-restoring a name-shaped string is the desired behavior and harms nothing real; (iii) ambiguous → suppress (safety default) and note for C6.
  - The scan runs on every derivation; NEW entries can't silently open FP surface at either level. The spec asserts NO concrete scan outcomes — the manifest is the source of truth and is reviewed.
- Manifest records: counts, additions, scan results, assertions passed. Parser AC compares file ↔ manifest.

## Matching design

Normalization: canonical mode = lowercase + NFD-fold + `’`→`'`; alias mode = lowercase + `’`→`'` (diacritic-EXACT). Output always canonical spelling.

Tokenization (symmetric): whitespace-split; (prefix, core, suffix) with edge punctuation peeled; apostrophes/interior periods stay in core. Entry tokens processed identically (`Aurora Drift: Last Signal` → cores `[aurora, drift, last, signal]`, with the `:` carried as that token's suffix for the validity exception).

Window validity: a multi-token window is invalid if any non-final token has a suffix or non-initial token a prefix — except where the ENTRY's corresponding token carries identical punctuation. **The exception applies to canonical-mode windows only; alias windows require plain validity** (aliases have no punctuation by derivation assertion). Alignment for the exception is positional within the window (entry token i ↔ window token i; canonical windows always have equal token counts, so alignment is total). **Windows never span a line break** (newline = window boundary, like sentence punctuation): real ASR output breaks lines mid-sentence, and firing across one would merge lines.

Known, deliberate false negative: apostrophes stay in token cores (so `O'Brien` matches), which makes quoted and possessive surfaces ('Vexa', ‘Vexa’, "vexa's") silent pass-throughs — a miss, never a corruption.

Single deterministic pass: left-to-right; at each position try windows longest→shortest (one length-indexed table containing canonical and alias keys; equal-length ties impossible by the collision assertions):
1. Alias hit (alias-mode) → replace with canonical, consume window.
2. Canonical hit (canonical-mode):
   - window string-equals canonical exactly → no correction, consume window;
   - else if every core ∈ effective suppression set → **suppress: no correction, advance ONE token** (a fully-suppressible entry never fires, whatever the diff — case-only or punctuation-bearing; it must not insert title punctuation into ordinary speech; restoration is wholly delegated to C6; shorter/alias windows at subsequent positions remain reachable);
   - else fire → replace with canonical, consume window. (A firing window with non-canonical inter-token whitespace is normalized to the canonical spelling, single spaces included.)
3. No hit → advance one token.
Replacement re-attaches first-token prefix + last-token suffix.

Determinism + idempotence by construction; property-tested.

## Output

`correct(_ text: String) -> CorrectionResult`: `correctedText`, `corrections: [Correction]` (`range` in ORIGINAL coordinates — verified by slice test, `original`, `canonical`, `stage: .exact/.alias`). Self-matches emit nothing.
