## Goal

The queue worker that delivers C1's `handoff_queue` items into the Evidence Store inbox on the remote host per the D4 contract — silently, in order, with retry until success, surviving crashes and offline periods, never losing or duplicating an item (hard floor 8). Plus the D4 payload assembly helper C7 calls. The app remains fully functional with the remote host offline.

## D4 payload assembly (`EvidencePayloadBuilder`, lives in C8, called by C7 — C1's "implemented in C7" wording is amended to "via the C8 builder")

Shape (a self-described JSON payload; the format is documented for consumers in `docs/handoff.md`):

```json
{
  "native_id": "<meeting ULID>", "source": "blaise",
  "title": "...", "started_at_ms": 0, "ended_at_ms": 0,
  "created_at_ms": 0, "updated_at_ms": 0,
  "owner": {"name": "<UserIdentity.name>", "email": "<UserIdentity.email>"},
  "attendees": [{"name": "..."}],
  "dominant_language": "pt",
  "summary_text": "<plain-text summary (structured.summary)>",
  "summary_markdown": "<rendered notes document>",
  "notes_structured": {...},
  "transcript": [{"speaker": {"source": "microphone|speaker", "diarization_label": "S0", "name": "..." | null}, "text": "...", "start_time_ms": 0, "end_time_ms": 0}],
  "provenance": {"asr": {...}, "notes": {...}, "pipeline_version": "..."}
}
```

- `speaker.source` = `"microphone"` iff the segment's resolved name matches the user's identity — **predicate pinned: case-insensitive, diacritic-folded equality against `UserIdentity.name ∪ aliases`** (the configured owner name and its aliases), OR the resolved name maps to an attendee whose email equals `UserIdentity.email`; else `"speaker"`. AC1 golden MUST include the alias-form case (a full-name alias of the configured owner → microphone). `owner` from UserIdentity. `attendees` carry `email` when known (`[{name, email?}]` — the knowledge graph's attendee canonicalization keys on email, r3 §3 — known emails must not be withheld). **Shape honesty: this payload is a self-described JSON shape, not mirroring any external format** — field names/units are deliberate (`*_ms` integer milliseconds everywhere — exactly HOW the no-floats determinism guarantee is achieved; `native_id` as the id). The format is documented for consumers in `docs/handoff.md`. `calendar_event`: omitted in V1 (documented). A consumer's own canonical-json hashing may differ from ours (escaping conventions diverge) — a consumer re-hashes payloads under its convention at ingestion and our `version_hash` is OUR idempotency key, not a shared one.
- **Canonical JSON, fully pinned:** the builder uses a purpose-built `CanonicalJSONWriter` (BlaiseCore, ~100 lines, exhaustively golden-tested): object keys sorted byte-wise; **no floats exist in the payload — every numeric field is an integer (milliseconds)**; strings escaped minimally (`\"`, `\\`, control chars as `\u00XX`; all other characters verbatim UTF-8); no insignificant whitespace; trailing `\n`. Value domain restricted to {string, integer, bool, null, array, object} — enforced at the type level. Determinism is by construction, not by encoder version.
- `versionHash` = SHA-256 of those bytes. `native_id` required in-payload (C1).

## Transport (D11): subprocess OpenSSH via SubprocessRunner

**Delivery invocation (normative; probed working form):** `SubprocessRunner` argv is exactly:

```
["/usr/bin/ssh", "-o", "BatchMode=yes", "-o", "ConnectTimeout=10",
 "-o", "ServerAliveInterval=15", "-o", "ServerAliveCountMax=2",
 "-o", "StrictHostKeyChecking=yes",
 "-o", "IdentitiesOnly=yes", "-i", <identityFile>, <user>@<host>,
 <remoteCommand>]
```

where `<remoteCommand>` is ONE argv element containing the full remote command string. **ssh space-joins remote-command arguments and the remote LOGIN SHELL re-parses the joined string** — a multi-element form is a probed parse error. The remote command string is built as:

```
find '<remoteDir>' -name '.tmp-*' -mtime +1 -delete 2>/dev/null; mkdir -p '<remoteDir>' && cat > '<remoteDir>/.tmp-<hash>-<nonce>' && A=$(/usr/bin/shasum -a 256 '<remoteDir>/.tmp-<hash>-<nonce>' | cut -d' ' -f1) && if [ "$A" = '<hash>' ]; then mv -f '<remoteDir>/.tmp-<hash>-<nonce>' '<remoteDir>/<hash>.json'; else rm -f '<remoteDir>/.tmp-<hash>-<nonce>'; exit 65; fi
```

**Injection safety is borne ENTIRELY by input validation, stated plainly (covering EVERY interpolated value):** `handoff.user` must match `^[a-z_][a-z0-9_-]*$`; each `handoff.hosts` entry must match `^[A-Za-z0-9.\-]+$` and not start with `-` (a leading-dash value in the user@host argv slot is OpenSSH option injection — `-oProxyCommand=` runs local code); malformed values → `configurationInvalid` worker pause. `<hash>` must match `^[a-f0-9]{64}$`; `<remoteDir>` = validated remoteRoot + "/" + ULID-validated nativeID, where `handoff.remoteRoot` must match `^/[A-Za-z0-9_][A-Za-z0-9/_.\-]*$`, contain no `..` path segment, no `'`, and no run of `//` (validation unit-tested with adversarial inputs: quotes, `$()`, backticks, spaces, `..`, leading `-`). Values failing validation never reach command construction — CONFIG failures (remoteRoot) pause the worker as `configurationInvalid` (items stay pending); PAYLOAD-side failures (invalid stored hash/ULID) quarantine that item as `damaged` (see Quarantine section). `StrictHostKeyChecking=yes` (both endpoints already in known_hosts — probed; first-contact trust is NOT acceptable for meeting content; a missing known_hosts entry surfaces as hostKeyMismatch with its one-time fix documented in README).

Payload bytes are the ssh process's stdin (`SubprocessRunner` gains an optional stdin-payload input — recorded C3 cross-spec amendment: stdin = caller-supplied Data, written from a detached task, fd closed at EOF; nullDevice remains the default). Temp name dot-prefixed, with a per-attempt `<nonce>` (16 lowercase hex, generated fresh per delivery attempt) so an orphaned post-crash ssh and a relaunch redelivery never write the same temp file. Stale-temp hygiene is the find-prepend IN the template above (the `;` isolates its exit code from the `&&` chain — probed).

**Per-delivery watchdog:** SubprocessRunner timeout = 120 s + 1 s per 100 KB of payload; expiry → SIGTERM/SIGKILL → transient failure. Keepalives (above) kill dead-TCP hangs earlier in the common case.

## Endpoint configuration (Settings keys `handoff.*`; defaults probed live)

- **`handoff.user` default `<user>`** — the handoff user is configured in Settings; the key authenticates that account directly.
- `handoff.identityFile` default `~/.ssh/id_ed25519` (the probed working key).
- **`handoff.hosts` (ordered list)** default `["<tailscale-host>", "<lan-host>"]` (Tailscale-first, LAN-second): each wake, the TCP probe tries hosts in order; the first that answers port 22 within 2 s is used for this cycle. Tailscale-first avoids the macOS Local Network prompt; if Tailscale is absent/down, the LAN address still drains the queue (its first dial may trigger the one-time Local Network prompt — documented in README as a possible one-time dialog, the bounded exception to silence). Observability names the active endpoint; "all endpoints down" is one breaker state.
- `handoff.remoteRoot` default `/Users/<user>/<store>/evidence-inbox/blaise`.
- Host-key mismatch (stderr `REMOTE HOST IDENTIFICATION HAS CHANGED` / `Host key verification failed`): NOT the generic 255 class — distinct `hostKeyMismatch` alert state, no retry burn (15 min floor), surfaced prominently via the snapshot.

## Builder inputs (pinned)

Every payload field's persisted source: `meeting` row (title, timestamps, attendees, dominantLanguage, asrProvenance), `transcript_segment` rows (text, timings, labels, names), `meeting_notes` row (markdown + **structured** — persisted since C2's migration v2 [the `structured TEXT NOT NULL` column], language, provenance), `UserIdentity` from SettingsStore. Re-materialization at delivery time therefore works from durable state alone. **Damaged-file replacement vs the immutable writer (ordering pinned):** re-materialize FIRST, compare the rebuilt bytes' hash to the stored `versionHash`; ONLY on match delete the corrupt file and write the verified bytes (delete-then-write of unverified bytes could manufacture a name/content-mismatched file). No match → `damaged:` quarantine, file left in place for diagnosis. A MISSING payload file is treated exactly as a hash mismatch: re-materialize → verify → write, the C1-promised recovery path.

## Quarantine + supersession (decision D12 logged)

- **C1 amendment (recorded in C1's spec changelog by this chunk):** C1's "failed is retriable bookkeeping" gains two RESERVED `lastError` prefixes owned by C8: `damaged:` (wake-exempt quarantine; relaunch re-checks once) and `superseded:` (terminal per D12). Consumers (C10 retry-all, any future logic) MUST treat prefix-reserved rows per these semantics; the prefix registry lives in one Swift constant (`HandoffErrorClass`) both C8 and C10 compile against — no string scattering. CHECK constraint untouched.
- `damaged` is for PAYLOAD-INTEGRITY failures only (self-check double-mismatch, validation failure OF THE PAYLOAD ITSELF like an invalid stored hash). **Configuration validation failures (remoteRoot etc.) are NOT damage**: an invalid setting pauses the WORKER (state `configurationInvalid` in the snapshot, loud), items stay `pending` untouched, and a settings fix + kick resumes everything immediately — the fixed-config-delivers-on-next-kick guarantee holds.
- **Supersession policy (D12):** when a NEWER handoff row for the same meeting reaches `delivered`, any older undelivered row for that meeting is terminally closed as `state='failed'`, `lastError='superseded:<newer hash>'` — content-superseded, not lost: the meeting's CURRENT content was delivered; the old version is reproducible from git-history-equivalent DB state if ever needed. This is the decided terminal state for the "permanent wedge" scenario (an older undelivered row that would otherwise never resolve). Logged in an internal decision record with this rationale.
- The DoD "queued items deliver in order" is scoped in docs + the final report as: healthy items deliver in strict enqueue order; quarantined/superseded items are visible exceptions, never silent.

## Queue worker (`HandoffWorker`, actor)

- **Drive:** wake on launch, `kick()` (from C7), `NWPathMonitor` change, retry timer. **Every external wake clears item backoff floors including the auth cap** — a fixed key delivers on the next kick, not in an hour. While items are pending, the worker holds a `ProcessInfo.processInfo.beginActivity(.background)` token (App Nap cannot stall timers indefinitely; path events + kicks remain the primary wakes).
- One delivery in flight (FIFO by `created_seq`).
- **Pre-stream self-check:** before each attempt, hash the on-disk payload; mismatch with `versionHash` → re-materialize via the builder → still mismatched → the item enters `damaged` alert state (lastError="payload damaged"), is SKIPPED by the FIFO scan (a poisoned item must not starve the queue forever — explicit, documented exception to strict ordering; the item is retried only on app relaunch or manual retry, and the state is loud in the snapshot + log). Hard floor 8 reading: the item is never DROPPED; it is quarantined visibly. Exit-65 from the remote (transfer corruption) stays a transient retry — the self-check has already proven local bytes match, so 65 means transfer/remote trouble, which retry fixes.
- **Two-level retry:** PER-HOST breaker state — a host answering TCP but failing ssh accrues strikes (3 consecutive → benched; TCP-probe failure benches immediately); bench duration = the breaker backoff (base 10 s ×2 jitter cap 5 min) PER HOST; **every external wake (kick/launch/path-change) clears ALL host benches and strike counts along with item floors** (the fixed-key-on-next-kick guarantee is breaker-inclusive). Item backoff: base 30 s ×2 jitter cap 15 min; auth floor 1 h, cleared by wakes. No give-up for transient classes.
- **Failure classification (probed):** exit 255 + "Permission denied (publickey" → auth; 255 + host-key strings → hostKeyMismatch; 255 otherwise → host-transient (breaker); 65 → transfer-transient; "No space left" → remote-disk (15 min floor); watchdog → transient; other → transient.
- **Crash safety:** orphaned ssh may complete after app death — harmless (idempotent `mv -f` of identical bytes; C1 sweep resets `delivering`; re-delivery no-ops). Graceful quit: SIGTERM via runner.
- **Observability:** the worker publishes an immutable `HandoffSnapshot` (Sendable value struct: state, activeEndpoint, pendingCount, currentItem {id, attempts, lastError}, damaged items, warning) to a `@MainActor @Observable` holder via `MainActor.run` — actor-to-UI isolation explicit.
- **Persistent-failure warning (D21, refining hard floor 8 by owner directive):** transient unreachability stays silent; persistent failure becomes visible. On every publish the worker evaluates `HandoffWarningThreshold.evaluate(items:configurationInvalid:now:previous:)` — a pure, unit-tested function over `HandoffRepository.undeliveredItems()` (every non-delivered, non-`superseded:` row, damaged quarantine included) — into `snapshot.warning`, passing the previously published warning as `previous`. A warning exists when any item is undelivered AND (some item has `attempts >= 3` with a non-transient-shaped latest error — `auth:` / `hostKeyMismatch:` — OR **any undelivered item is `damaged:`-quarantined, which is persistent IMMEDIATELY** (a damaged payload never self-heals, and because quarantine precedes the delivering claim its `attempts` never grows — waiting three attempts or an hour for it would be meaningless), OR the oldest undelivered item is older than 1 h regardless of error shape, OR the worker is paused `configurationInvalid`, which freezes attempts and cannot self-heal). **Episode memory (sticky episodes):** once a warning episode is active it carries `armedSeqs` — the undelivered `created_seq`s of the rows that armed it — and STAYS active while ANY armed row is still undelivered, even if the latest error class downgrades (auth → transient); it clears only when the armed set drains (delivery success or supersession). This closes the warn→clear→warn flap: a class downgrade can never clear the warning or mint a fresh episode (and a fresh notification) without a delivery actually succeeding. **Re-arm:** while an episode is armed, a GENUINELY NEW persistent failure must not be masked behind it. The episode re-arms — the `episodeKey` changes (re-notifies, un-dismisses the banner) and `armedSeqs` unions in the newcomer — when a persistent-shaped row (`auth:`/`hostKeyMismatch:`/`damaged:`) is present that is either (a) not yet in the armed set (a newly enqueued failing item) or (b) an already-armed row whose class escalated (transient → persistent) such that the freshly minted key differs. A plain transient downgrade, or a fresh transient row joining a stale queue, never re-arms — only the per-row persistent shapes do, preserving the anti-flap. The `HandoffWarning` value carries `since` (oldest enqueue), `meetingsWaiting` (distinct meetings), `shortReason` ("SSH key rejected", "host key changed", "the remote host disk full", "payload damaged", "handoff settings invalid", "the remote host unreachable", or the truncated raw error), `episodeKey` (latest-error class token + newest undelivered `created_seq`; attempts on the same failure keep it stable, a distinct error class or a newly enqueued item re-arms a new episode, and a sticky carry-forward holds the original key while no new eligible row appears), and `armedSeqs`. Warning clears (nil) on the first publish after the armed set delivers — silently. **Damaged-only liveness:** when nothing is deliverable but undelivered rows remain (a `damaged:`-only queue), the drain arms a re-evaluation wake at the oldest undelivered row's 1-hour staleness boundary before parking, so the stale arm is re-evaluated without an unrelated wake (the damaged-immediate rule already trips the warning at quarantine time). Surface policy (banner dismissal per episode, one notification per episode, persisted across relaunch, suppressed during the launch grace) lives in `HandoffStatusHolder`; the surfaces themselves are C10's (its spec).
- **`retryNow()` (the relaunch-to-retry fix):** re-enters retriable `failed` rows as `pending` (incl. one `damaged:` re-check; `superseded:` never — the C1/C8 prefix contract, same body as the queue panel's retry-all) and then external-wakes the worker, so all item floors and host benches clear and the head item is attempted immediately. Exposed to the warning banner, the menu-bar menu, and the Settings queue panel.
