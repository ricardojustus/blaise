## Goal

Record real meetings: system audio (Core Audio process tap) + microphone, crash-safe from the first second, into the existing pipeline — with a discreet menu-bar indicator and manual start/stop plus calendar-aware suggestions (B-6). TCC grants are the Human Touchpoint; everything else ships tested.

## Capture engine (`CaptureSession` actor, BlaiseCore)

- **One aggregate device** containing the global process tap (`CATapDescription(monoGlobalTapButExcludeProcesses: [selfAudioObjectID])` — exclude ourselves, where selfAudioObjectID is the HAL AudioObjectID resolved from our PID via `kAudioHardwarePropertyTranslatePIDToProcessObject` (the API takes AudioObjectIDs, NOT PIDs — research §1's warning); created via `AudioHardwareCreateProcessTap`) and the default input device: aggregate composed with `kAudioAggregateDeviceSubDeviceListKey` (the input device) + `kAudioAggregateDeviceTapListKey` (tap UID string) + drift compensation on BOTH sub-entries (`kAudioSubDeviceDriftCompensationKey`/`kAudioSubTapDriftCompensationKey`) per the research recipe → one IOProc, sample-aligned streams. Format from `kAudioTapPropertyFormat`. **Runtime facts confirmed by a real granted run of AC2 (10/06/2026, this Mac):** the mono tap delivers real mono system audio (the stereo+downmix fallback stays available in the converter but was not needed); the IOProc buffer order matches the composition (input-device streams before tap streams — tone-energy discrimination in the gated test); the tap's self-exclusion extends to descendant processes of the excluded process (their audio never reaches the tap — fine for Blaise, which must not capture its own sounds).
- **Device-change resilience (validated pattern):** default-output listener → full tap/aggregate teardown + rebuild on route change (AirPods); generation counter discards in-flight buffers across the swap; the FILES stay open — the tracks continue. Default-input changes likewise. Stale-aggregate cleanup at launch (a crashed session's aggregate device lingers — destroy by UID prefix `app.blaise.mac.`), guarded by a live-UID registry: an ACTIVE session's aggregate is never destroyed (start affordances work independently of launch ordering).
- **Crash-safe retention (probed: the ONLY surviving format):** each track records **LPCM Int16 16 kHz mono CAF** (`capture_system.caf`, `capture_mic.caf` in the meeting dir; ~115 MB/h/track, temp-class but retained until encode verifies). AAC-m4a and AAC-CAF are NOT crash-safe (no moov/pakt — probed dead). At stop: encode each CAF → `audio.m4a` / `audio_mic.m4a` via the C7 ingest encode path (verified decode gates CAF deletion — hard floor 2 end to end); the encode runs OFF the controller actor (the indicator flips to processing immediately via a `stopping` event, the session is released, and the next recording can start while the previous one finalizes — back-to-back meetings; the quit intercept awaits ALL in-flight finalizations via the controller's `awaitQuiescence()` — its own stop and a manual stop already encoding alike — before termination). **Startup sweep:** orphan `capture_*.caf` → encode + verify + attach + **auto-kick `processCaptured` (no babysitting)**; a meeting whose row is still `recording` is a LIVE session (the DB sweep at open already failed every crashed one) and is never touched — finalizing it would unlink the CAF under the live writer. If only one track's CAF verifies, encode the survivor, keep the truncated CAF on disk, flag via a THIRD processingNote writer class — **capture-recovery notes SURVIVE the next run's entry-clear (C7/C1 amendment recorded in both changelogs: run entry clears fallback/partial-regen notes but PRESERVES a capture-recovery note until a run completes with both tracks or the user dismisses it)**, transcript proceeds from the surviving track — honest partial, never a silent loss. **Launch re-dispatch:** meetings the DB sweep flipped to failed/"interrupted" that still have retained audio (`audio*.m4a`) are auto-kicked at launch (quit-during-recording leaves no CAF for the orphan sweep to key on); meetings the CAF sweep just kicked are excluded. **C1 amendment (recorded in its changelog): during capture, `capture_*.caf` are retention-class artifacts; their deletion happens ONLY through the single audited verified-encode function — plus one narrow start-failure exception: the controller deletes a just-created CAF stub after a failed capture start ONLY when a duration probe proves zero audio frames (no audio ever existed, so nothing is retained-class yet; anything unreadable or non-empty stays). C1's no-deletion-API claim is scoped to `audio*.m4a` plus these two paths.**
- Mic-silence health check: all-zero mic ≥ 60 s while system active → warning state; a graph whose input device exposes zero streams raises the same warning — emitted by the controller AFTER the `started` event (`CaptureStartInfo.micStreams`; an event during start would be erased by the state machine's start reset), and by the session itself at every graph build (effective on a route-change rebuild — mid-recording, no reset in play; at initial start it races the reset and the controller's post-started emission is the authoritative one). A rebuild that RESTORES a working input emits the clearing event — nothing else ever would (the detector restarts fresh and re-fires in 60 s if the new device is genuinely silent). The detector cannot fire on no data, so the build-time check is the only chance to warn. **Disk precheck at start (≥ 2 GB free) and a write-failure policy: a CAF writer error → immediate STOP + encode whatever exists + loud indicator alarm** (continuing to record into a failing writer loses MORE; this is the one sanctioned automatic stop). A stop that recovers NO track raises the same alarm. The alarm is a post-stop state, never recording-disabling: a new capture is startable from it, and it stays visible until dismissed from the menu or the next successful start. Quit-during-recording = the same stop+encode path (app delegate intercept).

## Two-track processing (`processCaptured(meetingID:)` — C7 pipeline variant; C7 spec changelog + body AMENDED by this chunk with the variant AND the regenerate dispatch)

Captured meetings have two retained tracks: ASR per track (two passes, same engine); MIC-track segments are created with **`speakerLabel = "user"` AND `speakerName = UserIdentity.name`** — `"user"` joins the reserved label classes (C1/C4 convention amended: `S<n>`, `unattributed`, `user`), and **apply() gains rule 0 (C4 amendment): segments labeled `user` are IMMUNE to any mapping** (no LLM proposal can rename the user's own voice). SYSTEM track runs diarization+merge as today; **isSelf hint events are EXCLUDED from system-track voting under two-track** (the user is not on that track — C4 amendment note). Interleave by start time; **tie-break: start, then track (mic first), then original ord; `ord` re-sequenced globally; the per-track monotonic/non-overlap invariants hold PER TRACK — cross-track overlap is legal (people talk over each other), recorded as a C4 post-condition scope note.** Correction/language/notes/finalize unchanged. **`speaker.source` durability (C8 amendment): the builder predicate becomes `speakerLabel == "user"` OR the name-match — label is durable in the DB, so re-materialization is exact.** **Captured dispatch key (durable): the `meeting.captured` column (migration v6, set at capture start) OR `audio_mic.m4a` presence → the two-track variant runs, in `regenerate()` and `dispatchProcessing()` alike. A captured meeting can never be silently halved by the single-track path — even when its mic track was lost, the captured variant still runs (isSelf voting exclusion, honest `capturedTracks`).** File-first `process()` untouched (imports never carry the flag or a mic track).

## Start/stop + calendar suggestions (B-6: manual satisfies V1)

- `RecordingSessionProviding` (C10's seam) implemented: starting a capture creates the Meeting row (`source` per picker: meet/zoom/teams/inPerson, `meetingCode` parsed from a pasted Meet link if provided, `startedAt = now`) and registers the live session (the C12 listener's live-correlation case activates).
- Start/stop from the menu-bar item + ⌥⌘R (in-app/menu-scoped — a global hotkey needs another TCC class, BACKLOG). Stop → `endedAt`, encode, `processCaptured` kicked.
- **Calendar suggestions (graceful, optional):** EventKit full access (macOS has no read-only level — `NSCalendarsFullAccessUsageDescription`, verified at implementation; its own TCC prompt; denied/absent → plain manual): events ±15 min from now with attendees/links surface in the menu as one-click starts (title + attendees prefilled; Meet code parsed from the location/notes URL). No calendar = plain manual. No auto-start in V1 (B-6; auto-detect signal documented for BACKLOG).
- Long-session WARNING at > 6 h (indicator state only; recording continues — the write-failure stop above is the only automatic stop). Status transitions stated: start → `recording`; stop → encode → `processCaptured` entry sets `processing` (C1 rules).

## Indicator (`MenuBarExtra`, discreet)

States: idle (template glyph), recording (subtle red-tinted glyph + elapsed time in the menu, ticking while open, NOT in the bar — calm), warning (mic-silence/long-session, while recording), alarm (loud post-stop failure: write failure / no recoverable audio; not recording, START stays available, dismissable from the menu, cleared by the next successful start), processing (spinner-adjacent glyph until finalize; START stays available — back-to-back meetings, recording wins the icon if both apply). Stop is two-phase to the indicator: `stopping` flips it to processing immediately, the encode result follows. Menu: Start/Stop, calendar suggestions, "Open Blaise", last-meeting quick link. No dock bounce, no notifications.

## Acceptance criteria

1. `scripts/test.sh` green. Unit (no TCC, no real capture): aggregate/tap descriptor construction (parameter snapshot tests against the research-verified forms); CAF writer format assertions + the orphan-sweep logic over planted CAF fixtures (incl. a truncated one — encode fails → CAF retained + surfaced); two-track interleave (synthetic segments, sample-aligned timestamps); processCaptured stage wiring with mock engines (mic-label path, system-diarize path, interleave, payload speaker.source); session lifecycle (start → Meeting row + live session registered; stop → endedAt + encode + kick); calendar-suggestion parsing (fixture ICS/EKEvent stubs → Meet code extraction); indicator state machine.
2. **Capture integration test (gated `BLAISE_TEST_CAPTURE=1`, requires the TCC grants):** 30 s real capture (play a 440 Hz fixture WAV through the default output during it), stop, verify: two CAFs grew, encode produced two playable m4as, the tone-energy discrimination confirms the mic/system track assignment (Goertzel; requires speakers — see the test header), and the kill -9 variant mid-capture (child-process harness, like C7's crash harness) leaves decodable CAFs that the startup sweep rescues + auto-kicks. **Both gated tests have RUN GREEN on this Mac (10/06/2026; the test host holds the grants).** They stay gated so ordinary suite runs record a skip-with-reason; the final acceptance gate re-runs them for the signed app at the Touchpoint.
3. Signing switch in build_app.sh + launch check green.
4. No regression (Swift + extension suites).
