# G5 — Generalized Handoff Destinations: Local Folder + Markdown Sidecar (v1)

**Goal.** Anyone's agentic system (Obsidian first) can consume Blaise output without SSH or the knowledge graph. Two additions; the SSH path is untouched. (publish_plan G5; D19.)

## 1. Design (settled)
- **Destination model:** `HandoffDestination` enum — `.ssh(HandoffSettings, markdownSidecar: Bool)` (existing SSH semantics incl. circuit breakers, plus the destination-independent sidecar flag) and `.localFolder(url: URL, markdownSidecar: Bool)`. Settings: a destination picker replacing the header's "the remote host" framing ("Evidence Store — where finished meetings are delivered"); SSH fields under the SSH choice; folder choice = NSOpenPanel with security-scoped bookmark persisted (sandbox-correct even though the app is not sandboxed today — bookmarks survive folder moves). The "Write Markdown sidecar (Obsidian-ready)" toggle is **destination-independent** (rendered next to the memory-digest toggle, OUTSIDE the per-destination fields) and applies to BOTH destinations; both read the single persisted key `handoff.localFolder.markdownSidecar` (name kept for migration), default ON.
- **Local delivery reuses the ENTIRE queue machinery** (states, retries, supersession, warning episodes (D21), Retry Now): the transport becomes a `LocalFolderTransport: HandoffTransporting` that (1) writes `<root>/<meeting-ulid>/.tmp-<hash>`, (2) verifies SHA-256 of the written bytes by **re-opening the temp from disk** (the local analogue of the remote `shasum`; an in-memory verify would be a tautology), (3) atomic-renames to `<hash>.json` via POSIX `rename(2)` (replaces an existing `<hash>.json` in one syscall — never remove-then-move, which would open a window where the visible file is absent) — the same verify-before-rename contract, same exactly-once guarantees, same inbox layout as an internal handoff note (the contract doc gains a "local destination" paragraph: identical layout, no host). **Atomicity is volume-dependent:** the temp and final share one directory, so the rename is a same-volume `rename(2)` — atomic w.r.t. concurrent readers on APFS/HFS+; on SMB/NFS it is protocol-dependent and iCloud-synced folders add a non-atomic sync layer (stated in the contract doc's local-volume caveat). Blaise never loses or duplicates regardless; the never-momentarily-absent property is best-effort on network/iCloud volumes.
- **Markdown sidecar (destination-independent toggle, default ON):** after the JSON delivery succeeds, deliver `<meeting-dir>/<slug(title)>.md` — YAML frontmatter (title, started_at ISO, attendees names, source: blaise, native_id, version_hash) + the already-rendered notes markdown.
  - **Local folder:** write the `.md` next to the JSON via `MarkdownSidecar.write` (one current sidecar per meeting; a slug collision between two distinct meetings sharing one folder gets a ULID suffix).
  - **SSH:** after the JSON delivery returns exit 0, UPLOAD the rendered `.md` to the SAME remote meeting dir via a second ssh invocation reusing the JSON's argv structure (user/host/identityFile) and transport, streaming the rendered bytes on stdin. Remote command (one argv element, login-shell re-parsed, every interpolated value single-quoted exactly like the JSON command): `mkdir -p '<remoteDir>' && rm -f '<remoteDir>'/*.md 2>/dev/null; cat > '<remoteDir>/<slug>.md'`. `remoteDir = remoteRoot + "/" + meetingID` (validated upstream: no `'`/`..`/`//`, ULID); `slug = MarkdownSidecar.slug(title)` is `[a-z0-9-]` by construction (the only new interpolated value, injection-safe; the worker asserts the charset and SKIPS rather than ever emit an unsafe command). The `rm -f '<dir>'/*.md` supersedes the prior-slug sidecar — the dir is per-meeting, so only this meeting's `.md` live there and the immutable `<hash>.json` history is untouched.
  - Sidecar delivery follows supersession (a newer version OVERWRITES the sidecar). Sidecar write/upload failure does NOT fail OR retry the delivery (JSON is the contract; sidecar is convenience) — it logs and retries on this meeting's next delivery.
- Errors: folder missing/unwritable/disk-full → the existing error classification (persistent after the D21 thresholds) → the warning surfaces. An unplugged external drive behaves like the remote host-offline: silent retry, eventual banner.
- ONE destination active at a time (V1.2 scope; multi-destination fan-out is BACKLOG).

## 2. Migration
Existing installs: current HandoffSettings map to `.ssh(...)` automatically; no behavior change; Settings shows SSH selected.

## 3. Acceptance criteria
- AC1: LocalFolderTransport unit tests — verify-before-rename (corrupt-on-write injected via the transport's read-back seam → no visible file, retry path), idempotent re-delivery, supersession closes older undelivered, `.tmp` hygiene.
- AC2: kill-mid-delivery (the C8 crash class) — kill between tmp-write and rename leaves only `.tmp-*`; relaunch redelivers; never a partial visible JSON. Reuse the C8 kill-test harness shape.
- AC3: sidecar — frontmatter golden (EN/PT titles incl. slug collisions: ULID-suffix on collision), overwrite-on-supersession, failure-isolated-from-delivery.
- AC4: D21 warning fires for a persistent local failure (folder deleted) with the folder-specific error class; Retry Now works.
- AC5: Settings round-trip — pick folder via bookmark, relaunch resolves it; SSH config untouched for existing installs (migration test on a settings fixture).
- AC6: end-to-end against a temp folder: meeting processed → JSON named by its hash (verify by recomputing) + sidecar present; payload bytes byte-identical to what the SSH path would emit (same builder — assert equality).
- AC7: suite green; pins unchanged; evidence contract doc bumped.
